# Minimal hosted architecture — 2026-11-03

Design recommendation for [issue 03](issues/03-minimal-architecture.md), implementing the [screen-eval-v1 domain contract](screening-evaluation-contract.md) without changing its rules. **Proposed implementation baseline, not a user-approved deployment decision.** No resources, subscriptions, application code or model-quality results are created by this research. [Primary-source runtime/cost comparison](architecture-sources.md) supports the provider facts; numerical application limits below are design choices.

## Recommendation and alternatives

Use one TypeScript application deployed to Cloudflare Workers Paid, D1 relational storage and Cron Triggers. Serve a small server-rendered HTML dashboard and JSON mutation endpoints from the same Worker using Hono, with runtime input validation using Zod and versioned SQL migrations. Use Vitest for public-boundary tests, TypeScript strict checking, Wrangler local development/deployment and a decimal library with logarithms/half-even rounding for the screening contract. Pin package versions in ticket 04 rather than assuming current versions here. Keep provider HTTP adapters thin and typed. No separate SPA or agent framework is necessary.

| Option | Benefits | Costs and trade-off | Disposition |
| --- | --- | --- | --- |
| TypeScript Worker + D1 + Cron | One deployable, managed SQL, scheduler and private-access integration; low idle cost | Scheduled invocations have finite wall/CPU/query limits; jobs must checkpoint. D1 storage/query limits require growth monitoring | Recommended; roughly $5 platform plus $1 archive/backup allowance |
| TypeScript Node process + SQLite + systemd timer on a small VPS | Ordinary Node APIs, no serverless per-invocation wall limit; transaction and timer model is simple | Investor owns OS/security updates, reverse proxy/TLS, disk incidents, off-host backups and uptime. Headline VM cost excludes backup/auth/domain/operations | Viable fallback if Worker compatibility or measured throughput fails; not selected for unattended personal operations |
| Managed application + managed Postgres + scheduler (Render example) | Conventional Node runtime and database, less OS work than VPS | Separate application, database and cron charges; persistent service costs consume more of the EUR 50 ceiling. Free services are not a dependable persistence/scheduling substitute | Credible but unnecessary for this load; revisit with measured Worker blockers |
| AWS AgentCore + supporting persistence/scheduling | Managed agent runtime and extensible tool ecosystem | Additional service boundaries, permissions and cost accounting; does not replace deterministic screening, SQL or publication rules | Optional later, no MVP need |

MCP would wrap the same two search/fetch capabilities while adding another protocol/server and trust boundary. Direct authenticated server-side HTTP adapters are smaller here. Neither MCP, AgentCore, vector search, microservices, SQS nor S3 is required. R2 is optional for bounded archival/backup exports, not part of transactional publication. D1 SQL remains authoritative; no vector similarity is needed for exact issuer/event identity and source-origin deduplication.

Private access uses Cloudflare Access with an explicit single-identity allow policy and JWT validation in the Worker (signature, trusted issuer, audience, expiry). Disable alternate workers.dev/preview routes in production or enforce the same validation there; never trust identity headers alone. Scheduled invocation has no public trigger endpoint. Browser mutations require authenticated identity, same-origin checks and CSRF protection. Access setup/domain/identity-provider availability must be verified in 04; an existing domain is not assumed. A new domain has a $2/month amortized allowance below. Until access works, do not expose real reports or credentials.

Deterministic code owns identity, clocks, calendars, numerical calculations, baseline order, lifecycle, selection eligibility, all budgets and publication. The model interprets bounded evidence and proposes typed conclusions; it cannot change rules, ranks, limits, database records or tools. A new main selection must be a validated subset of the exact frozen top-three queue. Early watch uses its own five-entry contract and cannot bypass screening.

## Storage and immutable publication

Store UTC instants plus IANA display/scheduling zones, stable security/issuer identifiers and exchange-session IDs. Persist decimal quantities as canonical decimal strings, not binary floating-point money. Use indexed relational tables and foreign keys for:

- Dated broker catalogues, identity/listing/type/issuer mappings, exceptions and calendars.
- Acquired daily bars, adjustments/actions and official-opening observations, including raw/split basis, source/feed/as-of/venue parameters, event/publication/acquisition times, hashes and revision lineage. Dedupe identical observations; conflicting arrivals append a revision/conflict.
- Snapshot manifests with acquisition cutoff, each input ID, all broker decisions, U_D and exclusions; metrics/full ranks, baseline, queue and candidate dispositions.
- Runs/stages/pages, leases/fencing generations, attempts, source/model reservations and actual usage, error codes and timing.
- Evidence IDs and independently retrieved canonical URLs, origin/event IDs, permitted excerpts/factual notes, publication/acquisition times, hashes, retention policy and replay gaps. Do not archive Brave search payloads/snippets without verified storage rights.
- Append-only assessments, reports, early-watch history, morning/refresh cohort membership and matching baseline freeze; lifecycle events, renewal intervals, review feedback, outcome revisions and optional purchase corrections.

Separate mutable staging/job state from published artifacts. Final publication is a single D1 atomic batch/transaction: validate expected run generation and frozen manifest; insert report, assessment references, decision dispositions, AI and baseline membership and freeze; mark publication committed. Unique keys on (report session, morning kind, rule version) and (run ID, assessment security, version) prevent retries publishing duplicates. A deliberate correction is an appended version linked to its predecessor, never an UPDATE of an existing assessment/cohort. Enforce this through repository write operations and SQL update/delete guards for published decision tables; controlled retention deletion must leave a tombstone/replay gap rather than silently alter a past claim. Report rendering reads only committed artifacts.

Publication time comes from the actual final commit attempt; the coordinator checks the clock immediately before the atomic batch. If transaction completion crosses the deadline, classify the result as late using completion time; never retain an earlier on-time flag. Store cutoff ≤ freeze/publication time and reject inputs first acquired after cutoff. Unknown publication time cannot support a time-sensitive claim. A partial report freezes its actual denominator and gaps. Baseline and AI share identical market input IDs. No LLM failure can erase the baseline or turn missing research into an evidence rejection.

Retain all published decisions, cohort membership and permitted calculation inputs needed to explain history; avoid retaining whole-universe minute data. Initially keep normalized whole-universe raw/adjusted daily rows and compact opening-reference records, not a duplicated 61/90-session copy per report. Snapshot manifests reference versioned rows. Cap fetched evidence to 256 KiB decompressed/document, at most 50 fetch attempts/day, and 100 MiB new retained evidence/month; retain only permitted useful excerpts/notes and hashes. This is not a grant of provider archival rights. Alpaca retention/cloud/LLM uncertainty remains the user's accepted limitation from 01; do not reopen its permission gate or send provider outreach. Do not send raw broker catalogues/account data or whole-universe bars to the model; use minimal candidate metrics with their semantics.

Target under 3 GB D1 working storage, warn at 2 GB, and measure indexed size/row writes monthly. At 3 GB, stop optional payload retention and export older permitted observation segments to compressed, immutable R2 archives with hashes/manifests and a tested rehydration path before removing D1 copies. Published manifests continue resolving archived input IDs; calculations either rehydrate or show unavailable, never silently lose history. D1's per-database hard limit remains binding even on Paid. If projected writes/storage/query work exceed the platform or budget allocation, stop new expensive work and propose migration rather than deleting outcome denominators. This archive step is capacity-triggered, not initial infrastructure.

## Jobs, scheduling and recovery

Cron wakes every five minutes in UTC; application code uses Europe/Zagreb and America/New_York plus the saved exchange calendar. Do not encode 08:00 Zagreb or 09:25 ET as fixed UTC offsets. Scheduled and manual work enter the same SQL coordinator. On US report sessions, start morning acquisition at 06:30 Zagreb, checkpoint until 07:45, close research at 07:50, and aim to publish by 07:55. At/after 08:00 the next tick records overdue/unavailable if publication is absent; a browser visit independently detects a missing current report from clock/calendar. These are proposed operational margins, not a measured SLA. Holidays/weekends skip report creation, while recovery, backups and any outstanding observations can still run. Verify spring/autumn US/EU DST mismatch and early closes.

Collect official-opening references for every saved U_D after open+45 minutes ET (30-minute auction window plus the verified 15-minute SIP exclusion), retry boundedly through the next exchange-report deadline. Persist misses/conflicts at the v1 initial deadline. Capture raw daily endpoints/actions for ALL saved-universe securities, including subsequently removed broker names and action successors, until their H30 data have matured. The current broker list never bounds historical outcome capture. Opening/endpoint acquisition must be operational in 05/08, before the outcome UI of 11 exists. Nothing collected after decision cutoff is research evidence for that decision.

A tick claims a bounded stage or page by conditional SQL update, incrementing a fencing generation. One pipeline coordinator lease serializes expensive work; lease lasts 90 seconds, each stage targets ≤45 seconds wall and ≤20 seconds CPU, and starts no new external call after its own 35-second work deadline. Provider/model calls have ≤20-second timeout; slow calls become a durable gap/retry. Production CPU configuration and actual scheduled wall limits must be checked in 04 against the source comparison. No invocation attempts the full workflow. Provider pages, screening per-security metrics and model turns checkpoint individually; final ranking over compact metric rows is a separate bounded stage. Benchmark the 5,078-input/90-session seed and decimal log calculations in 05/06. Partition or reduce stage work if measured memory/CPU/query limits fail; do not reduce the eligible universe.

Use keys (kind, session, rule version) for scheduled runs and (identity, command idempotency key) for manual commands. Successful retry returns the original result; same key with changed payload is rejected. Only one morning run exists per key. Manual refresh deduplicates its security set and queues behind the active stage, never changes a morning run. Existing active refresh returns its run ID. 10 enforces at most two accepted refresh runs per exchange session, a ten-minute cooldown and strictly-before-open-minus-five-minute successful completion for evaluated refreshes; the UI disables requests too late to fit. A late refresh is research-only. All refreshes share the global limits, not an extra paid allowance.

An expired lease can resume only from committed pages. Every write and publication checks its fencing generation; an old timed-out worker cannot publish. Retries use at most three attempts total per logical request (initial + two), bounded exponential backoff with jitter and Retry-After, deferred to a later tick instead of sleeping through an invocation. Never retry auth/permission/schema failures blindly. Count every attempt against request limits. A response lost after a paid call remains conservatively charged/reserved; no automatic refund or replay with fresh budget. Graceful failed/partial/unavailable run states preserve every committed artifact. Retry an incomplete run; a completed report requires an explicitly linked correction, not a new silent morning selection.

## Source and model safety, limits and spend

Select direct Anthropic Claude Haiku 4.5 as the initial **proposed** model, using a dated model ID verified in 07, no automatic model upgrades or expensive fallback. Its price supports the envelope; no actual assessment-quality benchmark has been run. 07 must evaluate a small fixed fixture pack (primary-source event, repeated wire copies, contradiction, no explanation, malicious source instructions, missing source and stale price) and document failures before unattended use. Use a strict validated structured result; one repair attempt is allowed within the same limits, otherwise insufficient evidence. Numerical predicates must reference deterministic supplied metrics, not model-generated levels.

Expose only typed `searchPublic(query, timeRange)` and `readSource(sourceId)` tools. Search has at most 300 query characters and no secrets/account identity. `sourceId` resolves through a server-owned registry of independently validated SEC/issuer/publisher URLs; the model never supplies an arbitrary fetch URL. The researcher can select among registered sources or request another bounded search to resolve a gap. It cannot browse authenticated sites, run code/shell, read files/environment, call broker trading routes, mutate state or contact people. Use explicit read-only endpoint allowlists even when a provider key itself is more capable. Do not grant trading permissions; no order/account/portfolio endpoints are needed.

All outbound HTTP destinations are policy controlled. Require HTTPS/443, reject embedded credentials, raw IP hosts, localhost/private/link-local/reserved ranges and metadata endpoints; normalize URLs and resolve/check all IPv4/IPv6 answers. For issuer/publisher retrieval use pre-vetted host allowlists, follow at most two redirects with full validation on every hop and bind the connection to the validated public destination. If Worker networking cannot enforce DNS/rebinding guarantees for an arbitrary host, reject it and retain the source link/gap; do not add an unrestricted fetch proxy. Fixed official API hosts are separately allowed. Cap decoded bytes/time, reject unsupported content types/archives/scripts and never execute HTML/JavaScript. Start with text/HTML/JSON/XML; unsupported PDF documents remain linked gaps until a bounded safe parser is added. Never forward browser cookies, auth headers or provider keys across redirects or to fetched pages. Render evidence as escaped text and sanitized links, never source HTML.

Treat tool output as untrusted quoted data with provenance, separate from system instructions; source instructions cannot grant tools or affect policy. Strip active markup and secret-like strings, minimize source text, and validate conclusions/citations against actually acquired evidence IDs and cutoffs. These controls reduce prompt-injection impact; prompts alone cannot guarantee immunity. The independent tool dispatcher and publisher enforce security regardless of model output. Never place secrets in the model context. Contradiction/abstention stays visible. Deduplication uses issuer, originating document/event and syndication evidence rather than URL count.

| Resource | Initial hard application limit, including retries/manual work |
| --- | --- |
| Search | 30 attempts/day; 1,000/month; $5 gross/month. Allocate up to 9 discovery, 10 tracked, 3 broad intake, 8 refresh attempts; unused slots may be shared without exceeding total |
| Source fetch | 50 attempts/day, 1,100/month; 256 KiB decompressed/response, 20 seconds/request; SEC ≤5 requests/sec globally (below published 10), observe provider Retry-After |
| Market requests | Token bucket ≤150 historical requests/minute against Alpaca's 200 limit; at most 600 routine requests/day including pagination/retries, 1,000 for an explicitly identified initial seed. If more are needed, checkpoint across days or show gaps; never truncate a universe silently. Broker/OpenFIGI have separate configured documented buckets |
| Model per security pass | At most 4 model turns, 12,000 aggregate input and 1,200 aggregate output tokens; repeated context/tool tokens count again. At most 6 tool dispatches within those turns and global source caps |
| Model per run/day/month | 60 turns per morning run, 100/day, 2,000/month; aggregate 180,000 input/18,000 output tokens per day, 6M/0.6M per month; $15/month gross hard reserve. Broad early-watch notes and repairs consume the same pool |
| Refresh | At most 2 runs/session; ten-minute cooldown; all shared request/token/spend limits apply |
| Platform/storage | $5 platform baseline + $1 initial storage/backup allowance; monitor platform usage daily, optional retention stops at projected allocation exhaustion |

Reserve worst-case dollars/tokens/requests atomically in D1 BEFORE each dispatch using configured price/model version, actual input estimate plus safety margin and explicit max output. Serialize reservations with conditional balances; concurrent calls cannot both spend the last allowance. Count retries, tools, cached/uncached inputs and any billed thinking at conservative published rates; disable unbudgeted provider web-search/agent tools and extended thinking. Reconcile actual usage when received, retaining the full reserve for unknown usage. Token estimates must never permit dispatch without a safe bound; reject oversized context. Fail closed if usage ledger/model price is unknown. Provider spend settings are additional controls, not substitutes for the local ledger. Budgets do not reset on retry, redeploy, month-boundary overlap or restore: key reservations by UTC billing month and reconcile outstanding calls before re-enabling jobs.

## Operating cost and failure behavior

Use [dated source prices](architecture-sources.md) and [data/search assumptions](public-research-check.md), no free credits or cached-token discounts. Data $0, Search $5, Workers Paid $5, storage/backup $1, model reserve $15, domain allowance $2 = **$28/month**. At assumed USD/EUR parity, add assumed 25% tax/FX reserve ($7) and EUR 10 contingency: **EUR 45/month**, leaving EUR 5 below the EUR 50 ceiling. This is a planning exchange/tax assumption, not an invoice or current FX quote; 04 verifies account-specific taxes/FX/domain before deployment. Model token maxima cost $6 input + $3 output = $9 at $1/M and $5/M respectively, leaving $6 within the $15 model reserve for price/usage uncertainty; dispatch still enforces both token and dollar bounds. The normal 13-security × 22-session maximum at 12k/1.2k tokens costs $5.148 before broad notes/refresh. Global daily/monthly caps may prevent optional work before those maxima; record gaps.

Cloud hosting variable charges and identity/domain billing cannot be guaranteed by an app ledger. 04 must configure available provider limits, disable unused services, measure representative load and document residual bill exposure before paid provisioning approval. Warn at EUR 35 projected all-in monthly cost; at EUR 40 projected operational cost stop optional refresh/early-watch work, then new LLM/search dispatch if needed to preserve reserve. Never buy a paid data plan automatically. If actual baseline charges exceed EUR 50, keep deployment pending and return the smallest concrete budget/scope choice to the investor.

| Failure | Observable behavior and recovery |
| --- | --- |
| Missing catalogue/calendar/required shortlist inputs | Current session unavailable, no new selections; keep last report visibly dated; resume pages after repair |
| Some identities/bars/auctions/actions absent | Partial denominator/exclusion ledger; no forward fills, proxy opening or zero outcomes |
| Search/model budget or service failure | Baseline retained; candidate unresearched/insufficient, no replacement stock; tracked check marked incomplete |
| Invalid/malicious evidence or model output | Reject source/tool/result; no unauthorized fetch, no unsupported citation or publication; bounded repair then gap |
| Crash, overlapping ticks or manual duplicates | Resume checkpoint under new fencing generation; original idempotency result retained; no second charge reservation without a counted attempt |
| Missed deadline | Missing/late banner; late report remains research-only, never on-time cohort; manual refresh never replaces morning |
| Database outage/storage cap | No publication or accepted mutation; private error/status visible when runtime allows; restore and reconcile before jobs resume |

Log run/session/stage IDs, duration, source host/status (no query payloads), counts, coverage, retries, budget reservation/usage, token model/version, freshness and error codes. Redact credentials, URLs with tokens, personal identity and raw source/model text from logs; keep structured run history 90 days and operational summaries longer in SQL. Dashboard shows last success, expected session, incomplete/failed stage, remaining budgets and next retry. No alerts/email are added. A platform outage may prevent a dashboard view; monitoring is lightweight, not a separate uptime guarantee.

Use D1 managed recovery plus a daily encrypted off-platform export with manifest/checksum, initially 7 daily and 4 weekly copies, bounded to the storage allowance. Ticket 04 must establish the real permitted backup destination and encryption-key custody; an encrypted copy in the same provider is useful but not independent disaster recovery. Keep secrets outside database/export/logs; store only secret names/config versions. Export and restore a clean disposable local database, verify row counts/hashes, foreign keys, immutable IDs, cohort totals and pending budget reservations; do not overwrite production to test. Target recovery-point ≤24h for exports and recovery-time one day after investor intervention; untested targets, not SLAs. Restore starts with jobs disabled; reconcile external usage and unrecoverable recent decisions, append explicit gaps and never backfill a lost historical selection from future evidence. Repeat restore exercise after schema changes and quarterly when operating.
