# Manual pre-opening re-review

Issue 10 adds private `POST /api/refresh` commands (`morningId`, `key`) and a same-origin CSRF-protected form on each morning report. JSON acceptance returns a durable `runId` and `nextTickDelaySeconds`; the form redirects to `/refresh/<runId>`. Reload that page for queued/running/completed/failed status and retained prior versions. Jobs and market capture must be enabled; existing defaults remain disabled.

The frozen request scope is the morning research three plus at most ten active tracked names, deduplicated. A tracked name appearing in both retains its recorded tracking thesis and a separate morning comparison identity. Refreshes reuse saved morning metrics, input hash, eligible universe and baseline; they never rerank or add discovery replacements. Tracking-only names never enter evaluated discovery membership. Successful tracked assessments append versions and lifecycle events without renewing the tracking checkpoint or replacing the recorded thesis. Confirmed issuer-text invalidation immediately marks the tracked thesis invalidated, even if the model accepts or fails. Daily tracking can continue from refresh versions.

Admission and command aliases are durable. Reusing a key with different morning input conflicts; overlap returns the existing refresh. SQL admission guards serialize concurrency, allow at most two accepted runs per exchange session, and enforce ten minutes between acceptances, including failed runs. Shared pipeline leases fence publication across manual and scheduled work. Each dispatch uses the existing research or market reservation ledger; unknown billed calls retain their charge and become a gap rather than replaying. No independent refresh budget exists.

`src/refresh/policy.ts` reserves twenty bounded stages per name, ten stages per tick, plus a terminal gap checkpoint per name and publication. Admission reserves whole five-minute ticks after the next tick and rejects a window that reaches the saved regular open minus five minutes. For three names this conservatively reserves 35 minutes after the next tick; for thirteen, 140 minutes. This is a conservative local allowance, not measured hosted capacity or a delivery promise; queued competing work or provider gaps can still make results incomplete/late. Each invocation uses the existing 1.5-second research-stage CPU allowance, at most ten stages, renewed 90-second leases, 35-second dispatch deadlines, 20-second provider/model timeouts and 240-second invocation envelope.

Source acquisition performs bounded announcement search, changed SEC filings, registered document reads and at most four model turns under the shared ledger. Missing issuer mappings, search configuration, unsupported links, budget exhaustion and model failures remain explicit gaps. Only permitted registered SEC excerpts are currently retrievable. Evidence acquisition/publication times are independently checked against the refresh cutoff. Later news cannot backdate a saved version.

Premarket acquisition queries a single raw SIP one-minute bar per name with its end at least fifteen minutes behind the acquisition clock, using the existing Alpaca request budget. Missing configuration, missing bars and request failures leave prices missing. The report shows source, raw basis, event/acquisition times, minute volume where present, minimum delay, and stale status when the observation is more than twenty minutes old. The saved raw completed-session close supplies a dated descriptive fractional comparison; corporate actions after the morning snapshot remain unverified. This raw comparison does not adjust an intervening split. Missing observations never establish unchanged conditions. Every result leaves current entry unvalidated and directs the investor to check Trading 212 live.

Publication atomically appends the refresh report, assessment versions, tracked lifecycle changes and matched AI/baseline manifests. Morning reports, decisions, cohorts and receipts remain unchanged. A primary-first readback verifies hashes, exact cohort manifest, assessment versions and morning input hash before sampling the actual availability clock. A separate immutable receipt certifies that observation. Only complete results observed **strictly before** open minus five minutes expose evaluated refresh cohorts. Equality, late recovery, incomplete work or missing receipt are research-only. Incomplete reports contain no cohort rows; manifests staged for otherwise complete but late/unverified publications are excluded by `RefreshPublication.get().evaluated` and its returned `cohorts`. Future outcome queries must apply that same receipt/completeness contract and keep every refresh separate from morning and from other refreshes.

Local validation includes refresh-command/publication seam tests, private HTTP authorization/CSRF, concurrent admission, cooldown/cap, strict cutoff equality, late readback recovery, post-cutoff news, atomic rollback, immutable versions, tracked overlap/invalidation, next daily tracking, stale/missing prices, unknown billed calls and coordinator completion. The encrypted recovery exercise includes pending refresh work and populated requests, aliases, reports, versions, cohorts and receipts.

Hosted combined throughput, actual provider minute-bar delivery/coverage, account permission/retention limitations, independent backups/key custody, Access/domain setup, live model quality, actual costs, three observed pre-08:00 mornings and human usefulness remain unverified deployment gates from the earlier runbooks. This change does not provision, deploy, enable jobs, execute trades, or make paid provider calls.
