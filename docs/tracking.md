# Tracked opportunities

Issue 09 adds manual tracking, separate from recorded purchases. Open **Tracked opportunities and daily changes** from the dashboard. A current main candidate has a **Track opportunity** form; occupied slots, lifecycle history and dated checks are available at `/tracking` and `/tracking/:securityId`. Archiving is explicit. Ten occupied records is a hard SQL limit, including needs-renewal records; concurrent last-slot selections cannot both succeed. Nothing here records ownership or sends alerts.

## Lifecycle and current reasoning

Selection records a stable security identity, an immutable accepted assessment and the original thesis version. Its first interval begins on the first exchange date on/after the selection date in New York. Session 20's saved regular close, including early closes, is the checkpoint. Calendar dates, rather than weekdays or UTC offsets, determine the interval. Missing forward calendar coverage rejects the command instead of guessing. A still-valid Friday assessment can be selected at the weekend, starting the next exchange session; a stale broker identity or expired assessment cannot become a new selection.

Expiry makes an assessment stale; it does not archive, invalidate, renew or release a slot. Observed confirmation of a recorded predicate marks the thesis invalidated, retains its original version and checkpoint, and publishes a new insufficient-evidence judgment when further research is unavailable. Active material-change checks continue until that checkpoint. At the close, the record becomes `needs_renewal` and source/model research pauses. Scheduled ticks, private views and command rules enforce the boundary. No item is silently archived to admit another.

Renewal requires an explicit command with a current accepted assessment whose market session matches the latest frozen snapshot. An invalidated thesis requires a later assessment rather than reuse of its invalidated reasoning. Renewal records a new thesis reference and begins a fresh 20-session interval on the next exchange date; it cannot be requested early. Prior intervals, assessment versions and checks remain accessible. A new daily assessment supplements the record but never resets tracking age or silently replaces the recorded thesis. Fixed-horizon opening/action/endpoint collection still uses saved eligible universes through H30, independently of tracking, archive and invalidation.

## Daily checks

The scheduled pipeline is capture → screening → discovery research → tracking → evaluation collection planning → morning publication. The tracking plan freezes at most ten occupied opportunities. Completed checks are immutable, embedded in that morning report and linked to full lifecycle/history pages. No active check in a report means **missing**, not unchanged. Paused records get a compact dated paused entry with no source/model work. Archival or renewal during a check yields a superseded check instead of overwriting the user's command.

Market predicates use the frozen SIP split-adjusted daily observations and decimal comparisons: absolute daily close return ≥5%, R20 movement ≥5 percentage points since the last assessment, changed momentum gates, latest volume / preceding 20-session mean ≥2, and a recorded close-below predicate. Frozen source IDs and market timestamps remain traceable. Missing comparable observations are material quality deterioration and an explicit gap. No missing return is converted to zero; no daily low or historical price becomes an executable stop or live entry check.

New acquired source text is compared with previously checked statements, origin/event identities and corrections. Identical repeated statements do not create a new material event or independent corroboration. Changed source content triggers conservative reassessment; text differences alone do not establish economic materiality, entailment or independent editorial origins. Unknown publication times remain gaps. The registered-source adapter is still SEC-only, and paraphrase/event identity limitations remain as documented in the research runbook.

New assessments can record independently checkable invalidation predicates alongside the cited condition: `close_below` references a supplied deterministic `sma20` or `latestClose` level, frozen at thesis recording; `source_text` references a cited origin and exact confirming text. Opaque prose conditions remain visible as requiring manual evidence review; they never fabricate confirmed invalidation. These are research invalidation conditions, not personal loss limits or trading instructions.

Discovery/tracking overlap shares acquired evidence. A discovery assessment is reused only when it addresses the same recorded thesis/conditions and covers newly acquired evidence; different reasoning requires a separate bounded assessment. Other tracked names get one announcement search, a mapped filings poll and up to three registered-source reads before material assessment. Unsupported links, read limits, unknown times, unavailable mappings, cutoff and budget exhaustion are durable gaps. All calls, tools, tokens, repairs and retained evidence consume the existing global ledger and per-pass limits; tracking does not create a second source/model allowance. Unknown paid calls keep their reservations and are not replayed automatically.

No-material-change entries retain the existing assessment ID and expiry; an expired assessment never becomes current merely because it was checked. Material updates append a new version linked to its predecessor. Incomplete material checks append insufficient evidence rather than a positive replacement. The report and detail page distinguish material changes, no established change, incomplete, paused and superseded states.

## Commands and recovery

All HTTP routes require the existing Access identity. POST `/api/tracking` accepts JSON with `action`, `securityId`, `expectedRevision`, `key`, and (for select/renew) `versionId`. Include the configured `Origin` and `/api/csrf` token in `X-CSRF-Token`. HTML forms use the same boundary and CSRF checks. Accepted commands return 201; HTML forms redirect. A stale revision, capacity conflict or unavailable current assessment returns 409; reload the current record before making a new command. A database failure returns unavailable rather than accepting a mutation.

Idempotency keys are scoped to the authenticated identity. Repeating an identical command returns its original result even after later state changes; reusing a key with different payload conflicts. Append-only lifecycle events atomically update the current projection, checking revisions and capacity inside the SQL transaction. Daily work checkpoints, pending dispatches, check publication and assessment/event publication use the existing fenced coordinator. The new migration adds SQL update/delete guards for lifecycle/check/version history. Encrypted export/restore includes these tables and pending tracking work.

## Remaining operational gates

Jobs, acquisition and research remain disabled by default. These local deterministic fixtures do not prove model semantics, arbitrary source coverage, all-ten tracked-name hosted throughput, budget fit under actual use, or completion by 07:50. Existing account/Access, source safety/retention, model quality, real-host CPU/query/heap, independent backups/key custody, cost and three observed pre-08:00 morning gates remain open. No provisioning, deployment, paid model request or provider outreach is part of this implementation.
