# Deterministic momentum screening

Issue [06](../.scratch/investment-intelligence-mvp/issues/06-momentum-screening.md) implements [screen-eval-v1](../.scratch/investment-intelligence-mvp/screening-evaluation-contract.md). These are prospective research rules, with no demonstrated predictive edge.

`screen({ manifest, observations, splitVolumeVerified }, ruleVersion)` is the pure calculation boundary. Supply a frozen snapshot and the exact observation versions listed in its decisions. It returns U_D, exclusions, measured signals, all momentum-passer ranks, issuer-selection dispositions, baseline and identical bounded research queue. Every broker decision survives, including missing inputs and nonpassers. An unavailable snapshot produces no new selections. A partial run retains its evaluated denominator; an empty universe has no median.

Use `Screener.step(lease, snapshotId, ruleVersion, partitionSize)` for durable execution. Each call saves up to 50 per-security metric rows by default (smaller partitions are supported). The next call skips committed rows; after all rows exist, one separate stage computes the universe median and final ranks using compact rows, then freezes all ranks, baseline and queue atomically. Research must wait for `Screener.result` to return a completed result. Input IDs stay in persisted metric rows; final ranking does not load the whole universe's bar histories or input-ID lists into memory.

`screening_metrics`, `screening_ranks` and `screening_results` are append-only and require the coordinator fence. Metric rows include exact frozen input IDs, identity, snapshot-specific sighting acquisition/action provenance, acquisition/event time limits and decimal measurements. The result includes snapshot ID, rule version, cutoff, expected session, denominator/counts, completion time and a SHA-256 input fingerprint. Inspect it through the existing private `GET /api/market/snapshots/:id?offset=0` API: `screening` is null until complete; rows paginate in the same 100-ticker order as snapshot decisions. Follow input IDs into the market-capture records for provider, symbol/as-of, basis, mapping/action version and acquisition receipts. The frozen snapshot retains calendar and source-receipt versions.

The market command now checkpoints a `screening` phase after qualification and before evaluation planning/completion. No extra provider request or model call occurs. The market invocation shares a 16-second reserved CPU-work allowance across all phases, leaving 4 seconds of the configured 20-second limit for coordination/serialization. Each screening stage reserves 1.5 seconds; query and CPU allowances both stop dispatch before another stage starts. These conservative local allowances require hosted validation. Existing frozen snapshots lacking explicit volume verification withhold volume confirmation; they cannot silently mix raw and split-adjusted activity. The current Alpaca adapter records verified split-adjusted volume semantics in new manifests. A manual capture defaults to unverified and must explicitly establish the same semantics before setting `splitVolumeVerified`.

Calculations use pinned [`decimal.js` 10.6.0](https://mikemcl.github.io/decimal.js/) with 90 significant digits, natural logarithms and 12-decimal-place half-even comparisons/ranking. `r20Calculation` retains the unrounded intermediate used for universe median and relative strength, so rounding displayed returns cannot create relative strength. The other saved metrics are comparison values at 12 places; UI formatting must never rerank them. Raw contemporaneous price × volume determines liquidity, and the latest raw price determines the price gate. Capture shares the same rounded eligibility comparisons. Adjusted closes/volumes determine return, trend, persistence and volume confirmation. Flat days do not count as positive; no positive log gains yields failed persistence, never division by zero. Provider daily activity can include extended sessions. Early closes count normally; rolling volume ratios can be distorted by early closes and event activity.

The baseline is the first three issuer-distinct passers, with fewer/zero allowed. Ranking uses RS20, R60, volume ratio, median dollar volume descending, then composite FIGI, share-class FIGI and ISIN ascending. All passer ranks and duplicate-issuer/outside-cap reasons remain visible. Repeated names keep their place. A research rejection or budget gap cannot change these saved records or backfill a fourth candidate. Research decisions and new/repeat presentation belong to issue 07.

`marketConfirmation` is `unconfirmed` for an eligible momentum nonpasser, `promotable` only for a passer inside the frozen research queue, and `confirmed_not_selected` for a passer outside it (including another class of a selected issuer). It is `ineligible` for exclusions, or `unavailable` when the run cannot support selection. Promotion still requires the evidence/research gates in issue 07; this flag alone is not a main selection. Early-watch event intake, ordering and expiry remain with issue 07.

Apply migration 0004 with the normal local migration workflow. The encrypted disposable restore fixture includes all three screening tables. The full-universe harness exercises all 5,078 securities and the 90-session raw/split seed, with 2,000 sustained paths so decimal logarithms are measured. It asserts each metric partition and compact final stage stay below its conservative 1.5-second CPU-work reservation in local elapsed time, and that the ten slowest measured stages together stay below the 15 seconds reserved for ten stages. Local elapsed time includes CPU and database waits, making it a conservative bound for the measured run. These local measurements bound local work; they do not establish billed Worker CPU, hosted heap/D1 limits, current provider coverage, combined morning completion or the outstanding three-session pre-08:00 operational gate.
