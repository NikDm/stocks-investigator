# Bounded evidence research

Issue 07 implements a local, checkpointed research stage after the frozen screener and before evaluation planning. It preserves the exact saved top-three queue and baseline. A rejected or unresearched member never causes backfill. This is research software, with no demonstrated investment edge or live morning readiness.

`ResearchRuntime` runs a bounded news/filings intake and then the main `BoundedResearcher`. Every step performs at most one model turn or one source/search request. Initial seed runs skip daily research/watch publication and do not dispatch paid research, preserving the real morning publication slot. The market coordinator renews its fenced lease between steps and charges a conservative 1,500 ms CPU allowance against the existing invocation-wide 16-second work allowance. Each request has a 20-second maximum and shares the stage/invocation deadline. These are application limits, not measured hosted CPU or a delivery SLA.

## Default and live gates

`RESEARCH_ENABLED` defaults to `false`. Missing configuration produces immutable `unresearched` candidate decisions and a partial early-watch result without outbound research calls. The screener remains readable. Jobs and market capture also retain their existing disabled defaults.

The proposed provider is direct Anthropic `claude-haiku-4-5-20251001`, without automatic upgrade or fallback. Its [official pricing](https://platform.claude.com/docs/en/about-claude/pricing) lists $1/M input and $5/M output tokens in the 2026-11-03 source check. An authenticated [model retrieval](https://platform.claude.com/docs/en/api/models/retrieve) check must return that exact ID before it is used. This implementation has not performed an account-specific check or a billed generation. Availability and live model quality remain unverified.

Live configuration consists of separately managed secrets `ANTHROPIC_API_KEY` and `BRAVE_SEARCH_KEY`, `SEC_USER_AGENT` containing the operator's SEC contact identity, and:

- `RESEARCH_MODEL_VERIFICATION`: JSON with `pricingVerifiedAt` (UTC milliseconds, at most 30 days old), `inputMicrodollarsPerToken: 1`, `outputMicrodollarsPerToken: 5`, and `qualityFixtureVersion: "research-fixtures-v1"`. This is an operator attestation following live evaluation, not something deterministic tests certify. Do not set it until the fixed fixture evaluation below has passed. Different/unknown rates fail closed.
- `RESEARCH_ISSUER_MAPPINGS`: at most 50 independently verified `{securityId, issuerId, cik}` records. Intake cross-checks the security and issuer against the current frozen U_D. This is an application-owned CIK registry, never model output. Missing mappings are coverage gaps. No whole-market filings coverage is claimed.

Keep all credentials out of source control, logs, database artifacts, model context and search queries. The runtime receives only these explicit research bindings; it does not load `.env`, account holdings, raw broker catalogues or whole-universe bars. Use the existing provisioning/billing/access checks in [operations](operations.md) before deployment. Account tax/FX, overall EUR 50 allocation and optional-work suspension remain operational responsibilities; do not enable optional research if the projected operating allowance is exhausted.

## Durable limits and recovery

Migration 0005 adds a single shared research ledger. An atomic fenced reservation precedes every dispatch; its trigger checks all relevant day/month/run/security-pass dimensions. All paths, retries, repairs and tracking/refresh callers use this ledger rather than create separate allowances. [Tracking](tracking.md) adds bounded daily change checks without a second source/model pool.

| Resource | Hard limit |
| --- | --- |
| Search | 30/day, 1,000/month, $5/month reserved at $0.005/attempt |
| Broad intake search | Three/day within the shared search limit |
| Source fetch | 50/day, 1,100/month, 256 KiB decoded response, 20 seconds |
| SEC | One request per 200 ms globally; contention is a gap, never a sleeping loop |
| Per-security model pass | Four turns, 12,000 repeated-context input tokens, 1,200 output tokens, six tools |
| Model totals | 60 turns/run, 100/day, 2,000/month; 180k/18k input/output per day, 6M/0.6M per month |
| Model spend | $15/month, integer microdollars, conservative 25% gross-up, no cache/batch discounts |
| Retained evidence | 100 MiB/month |

Input is conservatively reserved from encoded context bytes plus framing allowance; the provider adapter checks the [exact request token count](https://platform.claude.com/docs/en/api/messages/count_tokens) before generation. It sends plain Messages API text, with no provider search/agent tools, caching or extended thinking. Actual known usage reconciles once, never above the reservation. A contradictory usage response appends a durable halt blocking all further research reservations; investigate/reconcile provider billing and use a reviewed corrective migration before resuming. Unknown usage retains its full reservation.

Pre-dispatch checkpoints mark calls pending. Recovery does not replay a paid call with an unknown response. A pass becomes unresearched or intake records a gap. Auth/schema/source errors produce fixed codes without raw provider bodies. The researcher allows one structured-output repair within its original four-turn/token limits; a second invalid result becomes `insufficient_evidence`. Billed retries require new counted reservations; this stage deliberately makes no automatic retry after an ambiguous paid dispatch. SQL checkpoints, not browser requests, own continuation.

The durable tables are `research_calls`, `research_charges`, `research_halts`, `research_sources`, `research_evidence`, `research_plans`, `research_passes`, `research_intake`, `research_publications`, `research_decisions`, `research_assessment_versions`, `early_watch_publications` and `early_watch_history`. The encrypted disposable restore includes populated pending usage, evidence, published decisions, versions and watch history. Restore preserves outstanding reservations and pending calls; jobs remain disabled until the existing restore reconciliation is complete.

## Sources and trust boundary

The model may request only `search` with an application-generated ticker/topic query or `read` with a registered source ID. It cannot supply a URL, arbitrary query, tool, system policy, ranking, database mutation or publication command. The three broad queries are fixed application strings. Brave responses contribute URL metadata only: snippets/titles are discarded and never stored. Search URLs with credentials, queries, fragments or unsupported schemes are discarded.

The initial fetch allowlist consists only of fixed official SEC APIs: `data.sec.gov/submissions/CIK….json` for verified mappings and `www.sec.gov/Archives/edgar/data/<CIK>/<accession>/<document>` for documents. Registration is application-owned. Dynamic issuer/publisher hosts, private/raw IPs, credentials, non-HTTPS/443, redirects, PDFs, scripts/archives, unsupported types and oversized documents fail closed. The Worker cannot bind arbitrary DNS answers to a public connection, so there is deliberately no arbitrary-host fetch adapter. Unsupported publisher/issuer announcements remain linked retrieval gaps; they are not fabricated explanations. SEC filings and their issuer exhibits are the supported announcement path.

Source text is stripped of active markup and obvious secret-like strings, bounded and supplied under an untrusted quoted-data field separate from the system policy. It is never executable HTML. These controls reduce impact; they do not prove universal prompt-injection resistance. Private APIs return JSON and the existing page renderer escapes text. Any future dashboard evidence view must also escape text and sanitize links.

Origin independence uses the issuer origin, not the number of URLs or SEC documents. Application registration may supply an independently verified canonical `eventKey`. Without one, an issuer retains a conservative shared event identity, so textual revisions or different filing wrappers cannot establish a distinct event or restart expiry. A genuinely distinct event needs a separately verified key; the model cannot supply one. Multiple documents from one issuer never become independent editorial corroboration. Supporting third-party publishers requires a safe transport plus verified event/syndication provenance; arbitrary search results cannot grant themselves either. Semantic independence and event materiality remain quality-evaluation concerns.

Each acquired document retains a raw-content hash, sanitized excerpt, URL, origin/event IDs, first retrieval/publication times and predecessor when content changes. `replayGap: sanitized_excerpt_only` explicitly records that the original full document/HTML cannot be replayed. Source metadata and versions are append-only. Change review reads the newest 50 records, while publication also pins explicitly cited older evidence IDs. Original evidence remains usable only with its original cutoff; a later revision cannot rewrite it. Brave payloads have no assumed archival permission.

## Assessments and early watch

Unknown publication times cannot substantiate time-sensitive claims; only explicitly timeless background/context uses are allowed. Application validation checks strict structured output, exact quoted facts against acquired evidence, evidence/security identity and cutoff, citations on interpretations/thesis/invalidation, explicit uncertainty, a 20-session horizon, and supported deterministic `sma20`/`latest_close` price-condition methods. The model cannot invent numeric levels or grant itself acceptance/ranking/publication authority. Prose monetary targets and unsupported numbers are rejected; semantic entailment is a model-quality check, not something quote existence proves. Every price condition says `currentEntryValidated: false`; delayed historical market data never validate a live entry. Expiry defaults to the next scheduled report deadline. A structured opening/event dependency shortens it to the saved exchange opening or an application-registered scheduled event timestamp, with a cited event required. Missing or already expired dependencies fail validation.

Acceptance requires a supported thesis or an explicitly unexplained conditional market thesis, with cited invalidation. Contradictory facts withhold acceptance. Evidence-backed rejection is separate from unresearched infrastructure/budget failure. Insufficient evidence is a valid assessed outcome. Facts, interpretations, unknowns, contradictory facts, source timestamps, market as-of, expiry, model ID and independent-origin count remain inspectable. Causation is explicitly unverified. Final main selection orders supported theses before explicitly unexplained conditional market theses, preserving the frozen screener order within each group. Unexplained theses cite deterministic market metrics and retain an explicit explanation gap.

The publisher inserts all candidate dispositions and initial assessment versions atomically. Duplicate requests return the original publication; changed requests conflict. SQL update/delete guards protect published records. `appendVersion` requires an explicit predecessor and idempotency key and adds a correction; it cannot alter the original morning selection. These research artifacts do not certify on-time dashboard publication or evaluated cohorts. Issue 08 still owns morning dashboard assembly and its observed publication receipt.

Early watch performs three broad searches, up to three rotating verified-issuer filings polls, up to three document reads, and a bounded batch of short cited event notes. There is one note pass with at most one repair within the same ledger; there are no five extra full assessments. Sources and notes without a verifiable concrete recent event or identity become gaps/abstentions. Primary issuer events or two independent editorial origins in the last three exchange sessions qualify under the v1 domain contract; the current SEC-only adapter supplies only the primary path. Retained entries compete with new notes under primary source, capped independent count, publication time, and stable security order. Five issuer-distinct places is a cap, not a quota. Five-session expiry, distinct events, lost eligibility, disproven events, promotion and `confirmed_not_selected` history are preserved. Repetition of the same event never restarts its clock.

Inspect through authenticated `GET /api/market/snapshots/:id`: `research` and `earlyWatch` are structured committed artifacts alongside the original screening and coverage. No public research trigger, chat surface, alerts, email, purchase or trading feature is introduced.
